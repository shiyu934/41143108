## 解題說明
這次作業的目標是實作一個 Polynomial 類別，去表示多項式，並且支援以下功能：

讀入一個多項式（輸入運算子 >>）
輸出一個多項式（輸出運算子 <<）
多項式加法
多項式乘法
多項式代入數值後求值（Eval）

我怎麼表示一個多項式？

一個多項式可以看成很多「項」相加，比如

3𝑥^4−2𝑥^2+7

可以拆成：

係數 3、指數 4
係數 -2、指數 2
係數 7、指數 0

在我的程式裡，我用一個叫 Term 的 class 來表示「一項」，它有兩個成員：
```
float coef; // 系數
int   exp;  // 指數
```

然後我用 Polynomial 這個 class 來裝很多個 Term：
```
Term* termArray; // 用動態陣列存所有項
int capacity;    // 目前陣列最大容量
int terms;       // 目前實際用了幾個項目
```

一個 Polynomial 「一個 Term 陣列 + 有幾項 + 能放多少項」。

為什麼用動態陣列？

因為多項式的項數不一定一開始就知道，可能 2 項、也可能 20 項。

我用 new Term[capacity] 動態配置空間，如果不夠，就呼叫 Resize() 來擴充。

這個做法的好處是：不用決死寫死一個固定大小，也能控制記憶體自己釋放（有寫 destructor）。

怎麼讓它可以輸入/輸出？

有多載 operator>> 和 operator<<：

>>：讓使用者輸入幾項，然後逐項輸入係數和指數，存進 termArray。

<<：把整個多項式印出來，例如 3x^4 + -2x^2 + 7x^0 這樣。

這樣做的目的，是讓 cin >> p1; 和 cout << p1; 變得很自然，就像使用內建型別一樣。

怎麼做加法？

Add(const Polynomial& poly)：

我假設兩個 Polynomial 的項是按照指數由大到小排好。

用兩個 index (i 指向 this，多項式1；j 指向參數 poly，多項式2) 去「邊走邊合併」。

如果兩邊指數一樣 → 係數相加，當成同類項。

如果一邊的指數比較大 → 先把那一邊丟進結果。

怎麼做乘法？

Mult(const Polynomial& poly)：

我用雙層迴圈，把第一個多項式的每一項都去乘第二個多項式的每一項。

兩項相乘的規則是：

新係數 = 係數相乘

新指數 = 指數相加

如果結果裡面已經存在同樣的指數，就把係數加上去，而不另外再開一個新項。

我怎麼做代入求值？

Eval(float f)：

我把多項式每一項的值算出來再加總。

單項公式是：coef * pow(f, exp)
例如 
3𝑥^4代入 𝑥=2
x=2 會變成 
3∗2^4=48
總結來說，我的 Polynomial 類別就像是一個「可成長的多項式容器」，支援：

輸入
輸出
加法
乘法
代入求值

複製（我也有寫 copy constructor、operator=）

這些功能對應到題目要求的 ADT：可以建立多項式物件、對它做運算子操作、再把結果拿去印或評估。這也符合作業要求中「實作 Polynomial class 以及多載輸入/輸出運算子」。

### 解題策略

1. 直接依照數學定義寫成遞迴函數。

每一次遞迴都拆成更小的 m 或 n 推進，直到m=0 。

## 程式實作

以下為主要程式碼：

```cpp
#include <iostream>
using namespace std;

// 遞迴實作 Ackermann 函數
unsigned long long Ackermann(unsigned int m, unsigned int n) {
    if (m == 0) {
        return n + 1;
    } else if (n == 0) {
        return Ackermann(m - 1, 1);
    } else {
        return Ackermann(m - 1, Ackermann(m, n - 1));
    }
}
```
```
int main() {
    unsigned int m, n;
    cout << "請輸入 m 與 n: ";
    cin >> m >> n;

    cout << "Ackermann(" << m << "," << n << ") = "
         << Ackermann(m, n) << endl;

    return 0;
}

```
## 效能分析

這裡用 n 表示第一個多項式的項數（this->terms），m 表示另一個多項式的項數（poly.terms）。

(1) Add()

while 迴圈本質上同時往前走兩個陣列，最多各走一次

時間複雜度：O(n + m)
空間複雜度：O(n + m)（最壞情況沒有任何同次方可以合併，就把兩邊全部丟進 result）
這是高效的，因為我不是做巢狀比對；我只做一次「線性合併」。

(2) Mult()

用兩層迴圈，對於每個 this 的項，去乘上 poly 的每個項，所以乘法本身是 O(n * m)
但是還有一段「尋找同指數的項」：
```
for (int k = 0; k < result.terms; ++k) {
    if (result.termArray[k].exp == newExp) {
        ...
    }
}
```

線性搜尋 result，在最壞情況下可能再多一層，導致更慢。
在最糟情況（每次找不到一樣的 exp），result.terms 會成長，線性搜尋會越來越糟。最壞可能到 O(n * m * (nm))，也就是 O((nm)^2) 等級的行為。

實際上，因為很多乘積項會合併，所以沒有那麼誇張；現在這個做法不是最優。
更好的做法是用 map<exp, coef> 來 O(1)/O(log N) 找同次方，會變成 O(n * m * log(n*m)) 左右。

空間複雜度：最壞情況下，每對項都產生獨立新次方（沒有可以合併的指數），那結果多項式可能有 nm 項，所以是 O(nm)。

(3) Eval()

只是一個 for 走完所有 terms

時間複雜度：O(n)
額外空間複雜度：O(1)

(4) Resize()

Resize 不會每次都發生，只在容量不夠時擴大一次，然後複製已存在的 terms。
這是一種「動態陣列攤銷成本」概念：平均下來，append 新項的 amortized cost 還是接近 O(1)，不是每一步都 O(n)。

## 申論及開發報告

### 選擇遞迴的原因

在本程式中，使用遞迴來計算連加總和的主要原因如下：

1. **程式邏輯簡單直觀**  
   Ackermann 函數本身就是遞迴定義，遞迴程式碼能直接反映數學公式
   當 $m=0$ 或 $n=0$ 時，直接返回結果，結束遞迴。

2. **易於理解與實現**  
   程式結構簡潔清晰，使用遞迴可省略手動模擬堆疊或迴圈，使程式碼簡單且易於維護，例如：
```
unsigned long long Ackermann(unsigned int m, unsigned int n) {
    if (m == 0) return n + 1;
    else if (n == 0) return Ackermann(m - 1, 1);
    else return Ackermann(m - 1, Ackermann(m, n - 1));
}
```
3. **遞迴的語意清楚**  
在程式當中，每一次遞迴呼叫都對應一個「子問題」，最終結果會隨著遞迴逐層返回組合，完成計算。設計簡化程式邏輯，不需額外temp來儲存。

透過遞迴實作 Ackermann 計算，程式邏輯簡單且易於理解，特別適合展示遞迴的核心思想。然而，遞迴會因堆疊深度受到限制，當 $m $n 值過大時，應考慮使用迭代版本來避免 Stack Overflow 問題。
