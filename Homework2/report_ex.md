## 解題說明
這次作業的目標是實作一個 Polynomial 類別，去表示多項式，並且支援以下功能：

讀入一個多項式（輸入運算子 >>）

輸出一個多項式（輸出運算子 <<）

多項式加法

多項式乘法

多項式代入數值後求值（Eval）

我怎麼表示一個多項式？

一個多項式可以看成很多「項」相加，比如

3𝑥^4−2𝑥^2+7

可以拆成：

係數 3、指數 4

係數 -2、指數 2

係數 7、指數 0

在我的程式裡，我用一個叫 Term 的 class 來表示「一項」，它有兩個成員：

float coef; // 系數
int   exp;  // 指數


然後我用 Polynomial 這個 class 來裝很多個 Term：

Term* termArray; // 用動態陣列存所有項
int capacity;    // 目前陣列最大容量
int terms;       // 目前實際用了幾個項目


也就是說，一個 Polynomial 其實就是「一個 Term 陣列 + 我有幾項 + 我能放多少項」。

為什麼用動態陣列？

因為多項式的項數不一定一開始就知道，可能 2 項、也可能 20 項。

我用 new Term[capacity] 動態配置空間，如果不夠，就呼叫 Resize() 來擴充。

這個做法的好處是：不用決死寫死一個固定大小，也能控制記憶體自己釋放（我有寫 destructor）。

我怎麼讓它可以輸入/輸出？

我有多載 operator>> 和 operator<<：

>>：讓使用者輸入幾項，然後逐項輸入係數和指數，存進 termArray。

<<：把整個多項式印出來，例如 3x^4 + -2x^2 + 7x^0 這樣。

這樣做的目的，是讓 cin >> p1; 和 cout << p1; 變得很自然，就像使用內建型別一樣。

我怎麼做加法？

Add(const Polynomial& poly)：

我假設（也期望）兩個 Polynomial 的項是按照指數由大到小排好。

我用兩個 index (i 指向 this，多項式1；j 指向參數 poly，多項式2) 去「邊走邊合併」。

如果兩邊指數一樣 → 係數相加，當成同類項。

如果一邊的指數比較大 → 先把那一邊丟進結果。

這其實就很像合併兩個已排序陣列。

我怎麼做乘法？

Mult(const Polynomial& poly)：

我用雙層迴圈，把第一個多項式的每一項都去乘第二個多項式的每一項。

兩項相乘的規則是：

新係數 = 係數相乘

新指數 = 指數相加

如果結果裡面已經存在同樣的指數（同類項），我就把係數加上去，而不是另外再開一個新項。

我怎麼做代入求值？

Eval(float f)：

我把多項式每一項的值算出來再加總。

單項公式是：coef * pow(f, exp)
例如 
3𝑥^4代入 𝑥=2
x=2 會變成 
3∗2^4=48
總結來說，我的 Polynomial 類別就像是一個「可成長的多項式容器」，支援：

輸入

輸出

加法

乘法

代入求值

複製（我也有寫 copy constructor、operator=）

這些功能對應到題目要求的 ADT：可以建立多項式物件、對它做運算子操作、再把結果拿去印或評估。這也符合作業要求中「實作 Polynomial class 以及多載輸入/輸出運算子」。

### 解題策略

1. 直接依照數學定義寫成遞迴函數。

每一次遞迴都拆成更小的 m 或 n 推進，直到m=0 。

## 程式實作

以下為主要程式碼：

```cpp
#include <iostream>
using namespace std;

// 遞迴實作 Ackermann 函數
unsigned long long Ackermann(unsigned int m, unsigned int n) {
    if (m == 0) {
        return n + 1;
    } else if (n == 0) {
        return Ackermann(m - 1, 1);
    } else {
        return Ackermann(m - 1, Ackermann(m, n - 1));
    }
}
```
```
int main() {
    unsigned int m, n;
    cout << "請輸入 m 與 n: ";
    cin >> m >> n;

    cout << "Ackermann(" << m << "," << n << ") = "
         << Ackermann(m, n) << endl;

    return 0;
}

```
## 效能分析

1. 時間複雜度：程式的時間複雜度為 $O(log n)$。
2. 空間複雜度：空間複雜度為 $O(100times log n + \pi)$。

## 申論及開發報告

### 選擇遞迴的原因

在本程式中，使用遞迴來計算連加總和的主要原因如下：

1. **程式邏輯簡單直觀**  
   Ackermann 函數本身就是遞迴定義，遞迴程式碼能直接反映數學公式
   當 $m=0$ 或 $n=0$ 時，直接返回結果，結束遞迴。

2. **易於理解與實現**  
   程式結構簡潔清晰，使用遞迴可省略手動模擬堆疊或迴圈，使程式碼簡單且易於維護，例如：
```
unsigned long long Ackermann(unsigned int m, unsigned int n) {
    if (m == 0) return n + 1;
    else if (n == 0) return Ackermann(m - 1, 1);
    else return Ackermann(m - 1, Ackermann(m, n - 1));
}
```
3. **遞迴的語意清楚**  
在程式當中，每一次遞迴呼叫都對應一個「子問題」，最終結果會隨著遞迴逐層返回組合，完成計算。設計簡化程式邏輯，不需額外temp來儲存。

透過遞迴實作 Ackermann 計算，程式邏輯簡單且易於理解，特別適合展示遞迴的核心思想。然而，遞迴會因堆疊深度受到限制，當 $m $n 值過大時，應考慮使用迭代版本來避免 Stack Overflow 問題。
